# Cross-device sync uses Turso (libSQL) with the desktop as an embedded replica

**Status:** Proposed · 2026-09-14

The desktop keeps a local SQLite file, but `rusqlite` is replaced by the `libsql` crate opened as an **embedded replica with `remote_writes = true`**. Turso holds the source of truth: writes go straight to the remote, reads are served from the local file, and a background `sync_interval` pulls frames down. Mail-scan tables move to a separate, local-only database file that never syncs.

**Why:** In remote-writes mode the server allocates the `INTEGER PRIMARY KEY AUTOINCREMENT` ids, so the existing id scheme, foreign keys, and the frontend's `id: number` typing all survive untouched. Every other topology forces a migration to distributed ids (UUID or device-prefixed) across all 11 tables, all 7 `last_insert_rowid()` call sites, and the TypeScript layer — weeks of work before a single row syncs. Two devices writing to one remote is also ordinary row-level last-write-wins, which is correct for a single-user tracker; libSQL replicas sync WAL frames rather than rows, so any topology that allows concurrent offline writes diverges at the frame level and cannot merge. The schema is plain SQLite — no triggers, no FTS5, no `WITHOUT ROWID` — and all ~50 SQL call sites sit in Rust behind 59 Tauri commands, so the persistence boundary needs no redesign.

**Considered options:** Supabase (Postgres + RLS) and a self-hosted sync API, both from the earlier roadmap — each requires rewriting every query away from SQLite and building a sync protocol by hand; libSQL embedded replica with *offline writes* — keeps the desktop writable offline but reintroduces frame-level divergence and the distributed-id migration; one-way mirror into Turso with `rusqlite` untouched — cheapest, but the phone can only read; Turso with remote writes. Chose remote writes.

**Consequences:** `libsql` is async, so every SQL call site and its callers become `async`/`.await` — the colouring propagates through `mail_scan/` (`scoring.rs`, `accept.rs`, `persist.rs`), which is the bulk of the diff and the riskiest part, since that module also orchestrates a threaded sidecar. The desktop becomes read-only when offline; accepting that is the price of skipping the id migration. libSQL syncs whole files, so mail-scan scoring caches would otherwise push thousands of rows to the cloud per run — hence the split into a synced `app.db` and a local-only mail-scan database. Attachments stay local: `job_documents` holds filesystem paths, so PDFs do not reach other devices and clients must treat them as desktop-only rather than render dead rows. Migrations port unchanged; `PRAGMA user_version` and `AUTOINCREMENT` both work on libSQL. Turso free-tier row-read/write limits become an operational concern worth watching after the first sync-enabled release.
